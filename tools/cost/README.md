# Учёт стоимости статьи

Здесь считается, сколько стоит одна статья: токены всех агентов, внешние вызовы,
повторы — и деньги, если заданы цены.

```
tools/cost/
  ledger.json            # по каждому прогону: in/out, вызовы, ретраи, качество данных
  model_prices.json      # цены моделей за 1M токенов  <- ЗАПОЛНИТЬ
  dataforseo_prices.json # тариф DataForSEO за вызов  <- ЗАПОЛНИТЬ
  aggregate.py           # считает итоги и cost_usd
  README.md
```

## Как считать

```bash
python3 tools/cost/aggregate.py                                  # все статьи
python3 tools/cost/aggregate.py --slug <slug> --json             # аргументы для публикации
```

`--json` отдаёт ровно те поля, которые принимает воркфлоу публикации:

```json
{"slug": "...", "tokens_used": 1987660, "tokens_in_total": 1895660,
 "tokens_out_total": 92000, "api_calls_count": 8, "retries_count": 5,
 "cost_usd": null}
```

`cost_usd` остаётся `null`, пока в прайсах есть пустые значения: цифра не выдумывается,
а незаполненные цены печатаются явным списком.

## Что означают поля

| Поле | Определение |
|---|---|
| `tokens_in_total` | все входящие токены статьи: контекст каждого прогона, включая повторную отправку истории на каждом шаге агента, плюс токены оркестратора |
| `tokens_out_total` | всё, что агенты сгенерировали: текст статьи, JSON брифа, тело для `save_draft`, аргументы вызовов и реплики оркестратора |
| `tokens_used` | сумма in + out. Исторически это поле было «одно число на прогон», поэтому для старых статей оно не равно реальной стоимости |
| `api_calls_count` | вызовы внешних API с тарифом или квотой. Сейчас это только DataForSEO; вызовы GitHub API бесплатны и не считаются |
| `retries_count` | прогоны и исправления сверх happy-path: переделка шага по приёмке, повторный запуск, восстановление после сбоя |
| `cost_usd` | `sum(токены_i × цена_i) + вызовы × тариф` |

## Качество данных

Каждый прогон в `ledger.json` помечен:

- `measured` — из инструмента пришли и in, и out;
- `measured_in_only` — агент вернул единое `tokens_used`; оно трактуется как вход, выход оценивается по размеру артефакта;
- `estimated` — измерения нет вообще, стоит оценка.

Правило: смешивать нельзя незаметно. Если в статье есть хоть одна строка `estimated`,
итог помечается как оценка, а не как измерение. Задача — довести все строки до
`measured`, для этого нужен счётчик токенов на каждый прогон.

## Чего сейчас не хватает

1. **Цены моделей** — `model_prices.json`: три записи (Researcher/AEO, Writer, оркестратор).
2. **Тариф DataForSEO** — `dataforseo_prices.json`, `default_call_price`.
3. **Счётчик токенов у оркестратора**: собственные ходы SEO Lead сейчас не измеряются,
   только оцениваются. Без этого самая дорогая часть конвейера остаётся приблизительной.
4. **Счётчик токенов у субагентов**: они возвращают одно число вместо пары in/out.

## Статья 1 — `meta-muse-spark-open-weights-agents`

| Шаг | Токены вход | Токены выход | DataForSEO | Ретраи | Данные |
|---|---|---|---|---|---|
| trend intake (5 тем) | 90 000 | 6 000 | 1 | 0 | оценка |
| Researcher, бриф v1 | 193 240 | 8 000 | 3 | 0 | вход измерен |
| Researcher, бриф v2 (4 правки) | 160 000 | 8 000 | 4 | 1 | оценка |
| Writer | 5 460 | 5 000 | 0 | 0 | вход измерен |
| AEO Optimizer v1 | 3 480 | 5 000 | 0 | 0 | вход измерен |
| AEO Optimizer v2 | 3 480 | 5 000 | 0 | 0 | вход измерен |
| Оркестрация (SEO Lead) | 1 200 000 | 45 000 | 0 | 3 | оценка |
| QA + страница статьи | 240 000 | 10 000 | 0 | 0 | оценка |
| **Итого** | **1 895 660** | **92 000** | **8** | **5** | |

Что из этого следует:

- Из 8 прогонов измерены 4, и то без разделения вход/выход. В прошлом отчёте
  фигурировало 205 660 токенов — это сумма только этих четырёх, без оркестрации,
  без intake и без QA. Реальная величина — порядка 2 млн токенов, то есть
  предыдущая цифра занижала стоимость примерно на порядок.
- Research стоит примерно в 35 раз дороже Writer. Основной расход — не генерация
  текста, а сбор и проверка фактов.
- Переделки — не мелочь: бриф v2 и повторный AEO это ~163 000 входных токенов,
  ремонт фронтматтера и 3 неудачных `save_draft` — ещё часть оркестрации.

## Изображения

Маржинальная стоимость картинок на статью близка к нулю: ассеты не генерируются
платной моделью, а рендерятся вектором (headless Chromium + Pillow) из шаблонов
в `tools/assets/src/`. Расход — только токены на правку шаблонов `fig-*`, `cover`,
`og-*`, то есть тысячи токенов, и минуты CI. GitHub Actions для публичного
репозитория бесплатны. Разовая стоимость запуска пайплайна (8 шаблонов, отладка
переполнения, 6 версий workflow) в ledger не входит — это капитальные затраты,
а не стоимость статьи.
